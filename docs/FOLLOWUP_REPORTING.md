# Counsellor reminders and accountability

`/my-work` uses the existing unified workday API: personal follow-ups, assignment reminders, automation callbacks, demo tasks, appointments and unanswered WhatsApp conversations. Counts refresh every 30 seconds. Today and overdue overlap; they are not additive.

`/reports/follow-ups` is available to management and branch managers. A counsellor's personal evidence appears below their daily queue. The `GET /api/v1/follow-up-report/` endpoint enforces personal scope unless an authorized manager requests `team=true`. Branch scope is always enforced by Django. Optional filters: `start`, `end`, `branch`, `owner`, `category`, `page`, `export=csv`. Date boundaries are IST, inclusive, with a maximum 93-day period. CSV uses the same filters and is limited to 10,000 evidence rows; spreadsheet formulas in user-entered strings are escaped.

Task metrics use **due dates**, while contact-gap metrics use **enquiry creation dates**. Active assigned enquiries are a current total independent of date range. Tasks due is the sum of open current tasks and completed tasks in the period; pending excludes overdue. Reminder counts represent work items, not unique students. All evidence includes both task rows and separate deadline-history rows, so a task may appear twice in that view.

No contact recorded means a currently new enquiry has no outgoing call, answered call or accepted live staff message recorded since creation in its branch. Unanswered means an outgoing missed call is recorded, without an answered call or accepted live staff message since creation. Neither internal notes, assignment acknowledgement nor simulated messages establish student contact. No contact recorded is not proof that a counsellor failed to call. Call records are matched by contact and branch, so multiple enquiries for the same contact can share contact evidence. Student no-shows are not counsellor deadline failures; only overdue demo work counts as missed work.

`DeadlineMiss` stores a task's **first** missed deadline and original assignee. Completion, cancellation, rescheduling and reassignment through model saves or queryset updates preserve an expired deadline before changing a task. The existing automation cycle also snapshots overdue and completed-late work. Reports combine these saved records with currently overdue/completed-late tasks, without writing on GET. Subsequent misses of a rescheduled task are not separate breach events. This is task accountability, not a full history of every deadline revision.

Existing late completions and current overdue work are reportable. Cancelled work from before this feature cannot be reliably reconstructed, so no historic breaches are invented. Snapshot names/course details describe the original scoped work; links are withheld after a lead leaves the viewer's branch scope. Global managers can follow current enquiry links.

Apply migrations before starting the updated backend. Continue the normal Celery/Redis worker and beat deployment, or use `python manage.py process_automations --watch` for local development. Processing creates real staff tasks under enabled rules but message automation remains simulated. This feature does not activate rules, enroll students or send notifications. Reminders are in-app; email, push and live WhatsApp reminders are not added.
